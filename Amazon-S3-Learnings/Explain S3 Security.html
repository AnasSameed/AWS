What's the use of S3 CORS and object encryption and other S3 security and other stuffs

ChatGPT said:ChatGPT

Amazon S3 security is about protecting the files you store in AWS S3 from unauthorized access, data leaks, accidental deletion, and malicious attacks.

If you're learning AWS Cloud or preparing for a Cloud/DevOps job, understanding these concepts is important because S3 is commonly used to store images, videos, backups, documents, application files, and logs.

Let's break it down in simple terms with real-world examples.

1. What is Amazon S3?

viblo.asia

Amazon S3 (Simple Storage Service) is cloud object storage.

Think of it like Google Drive, but designed for applications, websites, backups, and enterprise systems.

  • Bucket: Main storage container.

  • Object: Individual file stored inside the bucket.

  • Key: The object's name or path.

  • Versioning: Keeps multiple versions of a file.

Example:

Plain text
my-company-bucket/ images/ logo.png product.jpg documents/ invoice.pdf backups/ database.zip

2. S3 CORS (Cross-Origin Resource Sharing)

Controls browser access

Purpose: CORS controls which websites are allowed to access your S3 resources through a web browser.

Imagine:

  • Your frontend website is hosted at https://mywebsite.com.

  • Your images are stored in an S3 bucket.

  • Your website wants to fetch images from S3.

The browser may block cross-origin requests unless the S3 response allows the requesting origin through CORS.

medium.com

Example CORS configuration:

JSON
{
  "CORSRules": [
    {
      "AllowedOrigins": [
        "https://mywebsite.com"
      ],
      "AllowedMethods": [
        "GET",
        "HEAD"
      ],
      "AllowedHeaders": [
        "*"
      ],
      "MaxAgeSeconds": 3000
    }
  ]
}

This allows the specified website to make GET and HEAD browser requests.

Important: CORS is NOT authentication or authorization. It doesn't prevent someone from accessing a publicly accessible object through another method.

3. S3 Object Encryption

Protects stored data

Purpose: Encryption converts readable data into unreadable ciphertext so that unauthorized parties cannot easily understand the stored information.

Imagine storing a customer database in S3.

Without encryption, a person who obtains the underlying data could potentially read it.

With encryption, the data is encrypted and requires the appropriate decryption key.

There are two important encryption situations:

A. Encryption at rest

Protects data while it is stored in S3.

storage.googleapis.com

Type

Meaning

SSE-S3

AWS manages encryption keys

SSE-KMS

AWS KMS manages encryption keys

DSSE-KMS

Dual-layer server-side encryption using KMS

SSE-C

You provide and manage the encryption key

Example: You upload an invoice PDF. S3 automatically encrypts it before storing it.

B. Encryption in transit

Protects data while moving between your application and AWS.

Example:

Plain text
Your application | | HTTPS / TLS | v AWS S3

This prevents network attackers from easily reading or modifying data in transit.

4. Other important S3 security features

These are particularly important for AWS interviews and practical projects.

A. Block Public Access

Prevents public exposure

Imagine you store 1,000 customer documents in an S3 bucket.

If someone accidentally makes the bucket public, anyone on the internet might access those documents.

Block Public Access prevents public access from being enabled through public bucket policies or ACLs.

Example:

Plain text
S3 Bucket | | Block Public Access = ON | X Internet cannot access publicly

There are four settings:

  1. BlockPublicAcls

  2. IgnorePublicAcls

  3. BlockPublicPolicy

  4. RestrictPublicBuckets

For private company data, generally enable all four.

B. IAM Policies

Controls who can access S3

IAM stands for Identity and Access Management.

It determines which AWS users, roles, or services can perform actions.

Example:

You have three employees:

Employee

Permission

Admin

Read, write, delete

Developer

Read and upload

Viewer

Read only

Example IAM policy:

JSON
{
  "Effect": "Allow",
  "Action": [
    "s3:GetObject"
  ],
  "Resource": "arn:aws:s3:::my-bucket/*"
}

This allows reading objects in the bucket, but doesn't allow uploading or deleting them.

Remember: IAM follows the principle of least privilege: give users only the permissions they need.

C. Bucket Policy

A bucket policy is a JSON-based permission policy attached directly to an S3 bucket.

For example:

  • Allow a particular application to upload files.

  • Allow only a specific AWS account to access the bucket.

  • Deny requests that don't use HTTPS.

Example:

JSON
{
  "Effect": "Deny",
  "Principal": "*",
  "Action": "s3:*",
  "Resource": [
    "arn:aws:s3:::my-bucket",
    "arn:aws:s3:::my-bucket/*"
  ],
  "Condition": {
    "Bool": {
      "aws:SecureTransport": "false"
    }
  }
}

This denies insecure HTTP requests and requires HTTPS.

D. Versioning

Protects against accidental changes

Imagine uploading:

Plain text
report.pdf

Then you accidentally upload another file with the same name.

Without versioning, the previous content can be overwritten.

With versioning:

Plain text
report.pdf | |-- Version 1 |-- Version 2 |-- Version 3

You can retrieve an older version.

Use: Recovering accidentally overwritten or deleted files.

Note: Versioning preserves previous versions; it doesn't automatically prevent deletion or replace a separate backup strategy.

E. S3 Object Lock

Protects against deletion

Imagine your company stores financial records that must not be deleted for five years.

Object Lock can prevent an object version from being deleted or overwritten during its retention period.

Two important modes:

  • Governance mode: Authorized users with special permissions can bypass retention.

  • Compliance mode: No user, including the account root user, can delete the protected version before retention expires.

There is also Legal Hold, which protects objects without a predefined expiry date.

Use: Financial records, audit logs, regulatory records, and ransomware protection.

F. Presigned URLs

Imagine you want to share an invoice with a customer.

You don't want to make the entire S3 bucket public.

Instead, generate a temporary URL:

Plain text
Customer | v Temporary S3 URL | v Specific invoice.pdf

For example, the URL may expire after 10 minutes.

The customer can access that particular object without receiving AWS credentials.

Use: Secure file downloads and uploads.

G. Server Access Logging and CloudTrail

These help you understand who accessed your S3 resources and what happened.

Service

Purpose

S3 Server Access Logging

Records requests made to your bucket

AWS CloudTrail

Tracks AWS API activity, including S3 operations

CloudWatch

Helps monitor metrics and create alarms

Example:

Plain text
User uploads file | v S3 | v CloudTrail | v Activity recorded

You can investigate who changed bucket permissions or deleted an object.

For detailed object-level read/write activity, configure the appropriate CloudTrail data events.

Amazon Simple Storage Service+1

H. Lifecycle Rules

Lifecycle rules automatically manage the storage and deletion of objects.

Example:

Plain text
Day 0 → Store in S3 Standard Day 30 → Move to S3 Standard-IA Day 90 → Move to Glacier Day 365 → Delete (if retention permits)

Use: Reducing storage costs and automatically managing old files.

I. Replication

S3 Replication automatically copies objects from one bucket to another.

Example:

Plain text
Bucket A (Mumbai) | | Replication v Bucket B (Singapore)

If you need disaster recovery, replication can help maintain another copy of your data.

There are two common types:

  • Cross-Region Replication (CRR)

  • Same-Region Replication (SRR)

Replication is not a substitute for a complete backup or recovery strategy.

J. S3 Access Points

Imagine five different applications need access to the same bucket.

Instead of managing all their access through one complicated bucket policy, you can create separate access points with different permissions.

Plain text
S3 Bucket | --------------------- | | | Access 1 Access 2 Access 3 | | | App A App B App C

Use: Managing access for multiple applications or teams.

5. Important difference: CORS vs IAM vs Bucket Policy

This is one of the most important things to understand.

Feature

What does it control?

CORS

Which browser origins can make cross-origin requests

IAM

Which AWS identities can perform actions

Bucket Policy

Who can access a particular bucket and its objects

Block Public Access

Prevents public access configurations

Encryption

Protects stored data

Versioning

Preserves previous object versions

Object Lock

Prevents deletion during retention

Presigned URL

Provides temporary access to a specific object

A common interview question:

"If I enable CORS, does that mean my S3 bucket is secure?"

Answer: No. CORS is a browser-level cross-origin mechanism. Actual authorization is handled through IAM, bucket policies, access controls, and related mechanisms.

6. Complete S3 security architecture

Here is how the different security layers work together.

ashishsrivastav.com

Think of security in five layers:

  1. Access security: IAM, bucket policies, access points.

  2. Network security: HTTPS, VPC endpoints, CORS.

  3. Data security: SSE-S3, SSE-KMS, encryption.

  4. Data protection: Versioning, Object Lock, replication.

  5. Monitoring: CloudTrail, CloudWatch, server access logging, Macie.
